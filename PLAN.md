# Plan: integrasi database + reaksi teragregasi

Status: **fase 1–7 selesai** (2026-10-21). Fase 8 (hardening + deploy) belum.

### Penyimpangan dari rencana awal

- Server ternyata **PostgreSQL 12.22** (client 16.9). Tidak ada `MERGE`/`gen_random_uuid`.
- Docker tidak dipakai; memakai instance Postgres yang sudah jalan.
- Kolom identity memakai `generated by default` — PG 12 menolak `DEFAULT` eksplisit untuk `generated always`.
- Tie-break emoji memakai `min(id)`, bukan `min(created_at)`: `now()` sama untuk semua baris dalam satu transaksi, jadi timestamp tidak bisa dipakai sebagai urutan.
- `POST /reactions` mengembalikan **semua** spot foto itu, bukan hanya spot yang berubah, karena perpindahan mengubah dua spot sekaligus.
- Fallback dev menurunkan user id dari id anonim browser, supaya dua browser bisa diuji sebagai dua user.

## 1. Ruang lingkup

Memindahkan seluruh state yang sekarang hidup di memori ke Postgres:

- foto + caption (sekarang `src/lib/data.ts`)
- reaksi per titik, dengan aturan satu user satu emoji per foto
- rating per user per foto
- identitas user dari `initData` Telegram
- tampilan pill teragregasi (stack emoji + total + `+N`)

Di luar lingkup: upload foto oleh user, moderasi, notifikasi, multi-bahasa.

| Area | Pilihan | Alasan |

## 2b. Setup database lokal (tanpa Docker)

Server yang berjalan adalah **PostgreSQL 12.22** (client `psql` 16.9, jadi jangan tertipu versi client). Instance ini dipakai bersama beberapa database lain, jadi semua langkah dibatasi ke role dan database baru:

```bash
sudo -u postgres psql -c "create role retpap login password '<generated>';"
sudo -u postgres psql -c "create database retpap owner retpap;"
```

`DATABASE_URL=postgres://retpap:<generated>@127.0.0.1:5432/retpap`

Konsekuensi PG 12 yang perlu diingat:

- `gen_random_uuid()` belum built-in (butuh `pgcrypto`) — skema ini tidak memakainya, semua PK pakai identity.
- Tidak ada `MERGE`; upsert memakai `insert ... on conflict do update`.
- `unique (id, photo_id)` untuk composite FK tetap valid.

## 3. Skema

```sql
create table users (
  id            bigint generated always as identity primary key,
  telegram_id   bigint not null unique,          -- sampai 52 bit
  username      text,
  first_name    text not null,
  last_name     text,
  language_code text,
  is_premium    boolean not null default false,
  photo_url     text,
  created_at    timestamptz not null default now(),
  last_seen_at  timestamptz not null default now()
);

create table photos (
  id           bigint generated always as identity primary key,
  slug         text not null unique,
  caption      text not null,
  image_url    text not null,
  image_width  int not null check (image_width > 0),
  image_height int not null check (image_height > 0),
  is_active    boolean not null default true,
  created_at   timestamptz not null default now()
);

create table reaction_spots (
  id         bigint generated always as identity primary key,
  photo_id   bigint not null references photos(id) on delete cascade,
  x          real not null check (x between 0 and 1),   -- relatif gambar
  y          real not null check (y between 0 and 1),
  created_at timestamptz not null default now(),
  unique (id, photo_id)                                  -- untuk composite FK
);
create index reaction_spots_photo_idx on reaction_spots (photo_id);

create table reactions (
  id         bigint generated always as identity primary key,
  photo_id   bigint not null references photos(id) on delete cascade,
  spot_id    bigint not null,
  user_id    bigint not null references users(id) on delete cascade,
  emoji      text not null,
  created_at timestamptz not null default now(),
  unique (photo_id, user_id),                            -- satu user satu emoji per foto
  foreign key (spot_id, photo_id)
    references reaction_spots (id, photo_id) on delete cascade
);
create index reactions_spot_idx on reactions (spot_id, emoji);

create table ratings (
  photo_id   bigint not null references photos(id) on delete cascade,
  user_id    bigint not null references users(id) on delete cascade,
  score      numeric(3,1) not null check (score between 1 and 10),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  primary key (photo_id, user_id)
);
```

Catatan:

- `reactions.photo_id` didenormalisasi supaya aturan "satu user satu emoji per foto" bisa ditegakkan database, bukan hanya kode.
- Composite FK memastikan `spot_id` benar-benar milik `photo_id` yang sama.
- `users.telegram_id` disimpan sebagai `bigint`, di JS selalu string (di atas 2^53 tidak aman).
- Agregat (avg, votes, count) dihitung saat baca; belum perlu kolom denormalisasi di volume ini.

## 4. Aturan bisnis di server

Semua dijalankan dalam satu transaksi per request:

1. **Toggle**: kalau user sudah punya reaksi di spot yang sama dengan emoji yang sama → hapus.
2. **Move**: kalau user sudah punya reaksi di tempat lain → pindahkan (`update spot_id, emoji`). Total spot lama turun, spot baru naik.
3. **Insert**: kalau belum punya → insert.
4. **Kapasitas**: maksimal 4 emoji berbeda per spot. Join emoji yang sudah ada selalu boleh; swap emoji sendiri juga boleh (karena menghapus dulu).
5. **Snap**: kalau client tidak mengirim `spotId`, cari spot terdekat dalam radius 0,04 dari lebar gambar, dengan koreksi aspek:
   `dx = x2-x1`, `dy = (y2-y1) * (image_height/image_width)`.
   Kalau tidak ada yang masuk radius → buat spot baru.
6. **Dominan**: `order by count desc, min(created_at) asc`. `min(created_at)` per emoji = urutan insert yang stabil.

## 5. API

| Method | Path | Body | Balikan |
|---|---|---|---|
| POST | `/api/session` | `{ initData }` | `{ user }` + cookie sesi |
| GET | `/api/feed` | — | `{ user, photos[] }` |
| POST | `/api/photos/:id/reactions` | `{ spotId?, x?, y?, emoji }` | `{ spot, myReaction }` |
| DELETE | `/api/photos/:id/reactions` | — | `{ spot: null, myReaction: null }` |
| PUT | `/api/photos/:id/rating` | `{ score }` | `{ avg, votes, mine }` |

Bentuk `spot` yang dikirim ke client:

```ts
{
  id: string;
  x: number; y: number;                 // 0..1 relatif gambar
  total: number;                        // jumlah reaksi (= jumlah user)
  myEmoji: string | null;
  reactions: { emoji: string; count: number; firstSeen: string }[];  // sudah terurut
}
```

Client tidak perlu menghitung dominan; server yang menentukan urutannya.

## 6. Auth

1. Client memanggil `POST /api/session` dengan `Telegram.WebApp.initData` mentah.
2. Server membangun `data_check_string`: semua field **kecuali `hash` dan `signature`**, diurutkan alfabetis, format `key=value`, dipisah `\n`.
3. `secret = HMAC_SHA256(key: "WebAppData", message: bot_token)`
4. Bandingkan `hex(HMAC_SHA256(key: secret, message: data_check_string))` dengan `hash`.
5. Tolak kalau `auth_date` lebih tua dari 24 jam (replay).
6. Upsert `users`, lalu set cookie `pap_session` (httpOnly, secure, sameSite=lax, 7 hari) berisi `{ uid, iat }` yang ditandatangani `SESSION_SECRET`.
7. Request berikutnya cukup membaca cookie; `initData` tidak dikirim ulang.

Dev fallback: kalau `TELEGRAM_BOT_TOKEN` kosong dan `NODE_ENV=development`, buat user dev dari header. Ditolak keras di production.

## 7. Koordinat (perbaikan bug)

Sekarang disimpan sebagai persen kontainer (`pap-card.tsx:140`), sementara foto memakai `object-contain` sehingga ada letterbox. Akibatnya titik yang sama jatuh di tempat berbeda saat aspek layar berubah.

Perbaikan: hitung kotak gambar yang benar-benar tergambar dari `naturalWidth/naturalHeight`, lalu simpan `(px - offsetX) / renderedWidth` dan `(py - offsetY) / renderedHeight`. Tap di area letterbox ditolak.

Ini juga membuat snap radius di server konsisten antar device.

## 8. Perubahan UI

**Pill per spot** (`ReactionPill` + `ReactionStack`):

```
[emoji depan][emoji kedua][+N]  total
```

- Maksimal 2 chip emoji, sisanya diringkas `+N` (N = jumlah jenis emoji yang tidak tampil).
- Chip depan = emoji milik user kalau ada, kalau tidak = emoji dominan.
- Chip depan diberi ring kalau itu emoji user.
- Angka di kanan = total seluruh reaksi di spot (= jumlah user).
- Gestur: 1 jenis emoji → tap toggle, hold buka picker. >1 jenis → tap buka picker.

**Info user**: avatar + nama di header (dari `users`), dan "Signed in as @username" di modal info.

**Rating**: slider mulai dari skor user kalau sudah pernah rating; perubahan = upsert, bukan vote baru. Header menampilkan avg + votes dari server.

**Foto**: dari tabel `photos`; seed menyimpan `image_width/height` (diukur saat seeding, bukan ditebak).

## 10. Risiko

- **Salah bangun data_check_string** (encoding atau ikut menyertakan `hash`) → semua login gagal. Diuji dengan initData asli, bukan karangan.
- **Presisi bigint**: `telegram_id` jangan pernah di-`Number()`.
- **Spot duplikat** kalau dua tap bersamaan. Diterima sebagai kosmetik; bisa dibersihkan dengan job.
- **Optimistic UI**: rollback harus mengembalikan spot asal, bukan hanya menghapus.
- **Rate limit**: satu user bisa spam toggle. Batasi per user per foto.
- **Gambar Unsplash**: `fit=crop&w=800` mematok crop, tapi dimensi harus diukur saat seeding.
- **Server dipakai bersama**: ada database lain di instance yang sama. Semua operasi hanya menyentuh role/database `retpap`; tidak ada `drop` atau perubahan pada database lain.
- **Beda versi client/server** (psql 16.9 vs server 12.22): jangan memakai sintaks yang hanya ada di PG 13+.
